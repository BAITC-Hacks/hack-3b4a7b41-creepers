# Creepers AI — Backend для чата ekt.kz

Прототип HackAlem AI 2026, кейс №1. FastAPI предоставляет каталог, ассистент с контекстом и основными ответами RU/KZ, анализ закупки, сравнение товаров и локальную корзину с обязательным подтверждением.

**Статус интеграции:** адаптер реализован по реальным авторизованным ответам `/products`, `/products?page=2`, `/products/detail?id=515291`. Цена, артикул, название, остаток и поддерживаемые характеристики приходят из EKT. Пароль хранится только в локальном `.env`; на другом компьютере его нужно настроить отдельно.

Проверка 23.09.2026: три обязательных запроса с Basic Auth успешны; без реквизитов API возвращает 401. Uvicorn отвечает `/health` и публикует OpenAPI. Сквозное демо прошло **с настоящим каталогом**, включая проверку остатка, характеристики, отсутствие сертификата, подготовку и подтверждение 5 единиц. Для нулевого остатка подходящего аналога в просмотренных страницах не найдено; синтетический тест отдельно проверяет успешный подбор альтернатив.

## Стек и архитектура

Python 3.12+, FastAPI, Uvicorn, async httpx, Pydantic, pydantic-settings, python-dotenv. Тесты: pytest, pytest-asyncio, httpx MockTransport/ASGITransport.

```text
Backend/
  app/
    main.py, config.py
    api/       health, products, chat, cart
    clients/   ekt_client.py: HTTP Basic Auth, ошибки, единственная граница EKT JSON
    services/  products, stock, alternatives, sessions, cart, conditions
    agents/    intent.py (чистые правила), tools.py (фасад сервисов), assistant.py
    schemas/   нормализованные product, chat, cart, attachment
    core/      ошибки и настройка логирования
  scripts/     inspect_ekt.py, demo.py
  tests/       изолированные тесты без реальных реквизитов доступа
  .env.example, .gitignore, requirements.txt, pytest.ini
```

`API → assistant/service → EktClient → EKT`. Только сервис корзины меняет корзину. Сессии и ожидающие действия находятся в памяти; операции каждой сессии защищены одним async-lock. Для основных сценариев LLM и AI-ключи не требуются. Опциональный OpenAI-разбор расширяет понимание нераспознанных запросов; полная локализация интерфейса остаётся следующим этапом.

## Установка и запуск (PowerShell)

Из корня проекта:

```powershell
cd Backend
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
# Только если .env ещё нет; существующий файл не перезаписывать:
Copy-Item .env.example .env
# Впишите пароль локально в .env, не отправляйте его в чат и не коммитьте.
.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

Linux/macOS: `python3.12 -m venv .venv`, затем `.venv/bin/python -m pip install -r requirements.txt` и `.venv/bin/python -m uvicorn app.main:app --reload --port 8000`.

Swagger: <http://127.0.0.1:8000/docs>. OpenAPI: <http://127.0.0.1:8000/openapi.json>. `/health` подтверждает работу приложения, **не доступность EKT**.

## Подключение реального EKT API

1. Заполнить локальный `.env`, **не `.env.example`**. После изменения `.env` перезапустить Uvicorn: `.env` не всегда отслеживается перезагрузчиком.
2. Выполнить `.venv\Scripts\python.exe scripts/inspect_ekt.py`. Скрипт обращается только к трём документированным GET-запросам, выводит ключи/типы JSON и размеры массивов, не выводит значения полей, заголовки и пароль.
3. Запустить тесты и `scripts/demo.py` против работающего сервера.

Реальный wire-формат и всё сопоставление сосредоточены **в `app/clients/ekt_client.py`**: `EktPage`, `EktListItem`, `EktDetail`, `EktResponseAdapter`. Снимки ответов без реквизитов находятся в `tests/fixtures/ekt_verified.json`; это регрессионные данные, не текущие остатки/цены. `SyntheticAdapter` используется только в тестах.

Проверенные соответствия:

| EKT | Нормализованное поле / поведение |
|---|---|
| `items`, `page`, `per_page`, `count` | Страница каталога; `count` — число элементов текущей страницы, не общее количество |
| `id`, `article`, `name`, `price` | ID становится строкой, остальные значения берутся напрямую |
| detail `quantity` | `stock`; значения отдельных `stores` не суммируются |
| detail `properties` | Подтверждённые поля тока, напряжения, полюсов, отключающей способности, установки, назначения, устройства, характеристики срабатывания и марки |
| `url` | `product_url`; путь раздела без последнего сегмента → `category`, `category_source:catalog_url` |
| `image`, detail `description` | `image_url`, `description` |

Отдельной категории с человекочитаемым названием, валюты и сертификатов в проверенных ответах нет. Категория — исходный путь раздела каталога, а не придуманный перевод. `RECOMMEND` не считается списком аналогов. `KRATNOST_MIN` не интерпретируется как общие условия минимального заказа. Смысл непроверенных свойств и вариантов `offers` не угадывается.

Если API вернёт непустой `offers`, карточка получает предупреждение и неизвестный остаток: добавлять родительский товар с неразобранными вариантами нельзя до проверки их структуры.

Обнаруженная особенность: слишком большой `page` может вернуть товары первой страницы с запрошенным номером. Поиск останавливается при повторении идентификаторов и сохраняет `partial:true`. Отсутствие надёжного total/next не подменяется значением `count`.

В карточке `515291` название/описание содержат 160А, а свойство `NOMINALNYY_TOK` — 250 А. Исходные значения сохраняются, `data_warnings` сообщает о противоречии, товар исключается из подбора аналогов. Нельзя считать такое свойство подтверждённой характеристикой без уточнения у поставщика.

Пустое поле в API остаётся `null`, `{}` или `[]` по контракту. Stock `0` → `out_of_stock`, положительный → `in_stock`, неизвестный → `unknown`. Неверные отрицательные значения отклоняются. Никакие реальные cart/search endpoints, не указанные партнёром, не используются.

## API-контракт для фронтенда

| Метод и путь | Запрос | Ответ |
|---|---|---|
| `GET /health` | — | `{"status":"ok"}` |
| `GET /api/status` | — | Режим, наличие настроек и условия покупки; секретов нет |
| `GET /api/products?page=1` | `page`: 1–50 | `{products,page,has_next}`; `has_next:null` означает неизвестное продолжение |
| `GET /api/products/search?q=25A` | `q`: 1–200 символов | `{products,query,scanned_pages,partial,message}` |
| `GET /api/products/{product_id}` | ID | Нормализованный `Product` |
| `GET /api/products/{product_id}/alternatives` | ID | `{product,alternatives:[{product,reason}],partial}` |
| `POST /api/chat` | `{session_id,message}` | Фиксированный контракт ниже |
| `POST /api/cart/prepare` | `{session_id,product_id,quantity}` | `{pending_confirmation:true,product,quantity,available_stock,message}` |
| `POST /api/cart/confirm` | `{session_id}` | `CartResponse` |
| `POST /api/cart/cancel` | `{session_id}` | `{message,cancelled,cart}` |
| `GET /api/cart/{session_id}` | session ID | `CartResponse`; неизвестная сессия → 404 |
| `POST /api/chat/attachments` | multipart: `session_id`, `file`, необязательный `recognize_image` | Метаданные, статус извлечения, текст, необязательный `procurement`, `candidates`, `demo_recognition` |
| `GET /api/chat/procurement/{session_id}` | session ID | Отчёт закупки; отсутствующий → 404 |
| `POST /api/chat/procurement/select` | `{session_id,row_index,product_id}` | Обновлённый отчёт после выбора разрешённого кандидата; корзину не меняет |

`session_id`: 1–128 латинских букв, цифр, `_`, `-`. Фронтенд должен генерировать случайный UUID и сохранять его для всей беседы. Это идентификатор прототипа, а не полноценная авторизация. Product ID передаётся строкой. `quantity` — строго целое число 1–1000000, не строка и не boolean.

`Product`: `id`, `article`, `name`, `category`, `specifications` (словарь строк), `certificates` (массив строк), `price`, `currency`, `stock`, `availability`. `price`, `stock`, `available_stock` сериализуются десятичными **строками** или `null`, чтобы не терять точность. Валюта не подставляется по умолчанию.

Дополнительные поля: `category_source`, `description`, `product_url`, `image_url`, `data_warnings` (массив предупреждений о качестве данных), `source` (`ekt_catalog` или `demo_catalog`). Показывайте предупреждения и источник рядом с характеристиками. Все обязательные ранее согласованные поля сохранены.

Ответ чата:

```json
{
  "message": "...",
  "intent": "product_search",
  "products": [],
  "alternatives": [],
  "pending_confirmation": null,
  "cart": null,
  "checkout_url": null,
  "error": null
}
```

При подготовке `pending_confirmation` содержит объект ответа `/cart/prepare`. `cart` содержит `{items:[{product,quantity}],total_items,checkout_url}`. `total_items` — сумма количества, не число строк. Обработанные бизнес-ошибки чата возвращаются HTTP 200 с `error:{code,message}`; ошибки валидации — 422 с теми же полями контракта. Остальные API используют HTTP 4xx/5xx и `{error:{code,message}}`. Фронтенд должен проверять `error`, а не только HTTP-статус.

Ошибки включают: `ekt_not_configured` (503), `ekt_timeout` (504), `ekt_unavailable` (503), `ekt_auth_error`/`ekt_http_error`/`ekt_invalid_json`/`ekt_invalid_product` (502), `product_not_found`/`session_not_found` (404), `insufficient_stock`/`stock_unknown`/`pending_action_missing`/`pending_action_expired` (409), `validation_error` (422). Реквизиты доступа и тело upstream-ошибки не возвращаются.

## Примеры запросов

С настроенным `.env` и запущенным сервером:

```powershell
Invoke-RestMethod http://localhost:8000/health
Invoke-RestMethod 'http://localhost:8000/api/products/search?q=25A'
Invoke-RestMethod http://localhost:8000/api/products/515291
Invoke-RestMethod http://localhost:8000/api/chat -Method Post -ContentType 'application/json; charset=utf-8' -Body '{"session_id":"demo-session","message":"Найди автомат 25А"}'
Invoke-RestMethod http://localhost:8000/api/cart/prepare -Method Post -ContentType application/json -Body '{"session_id":"demo-session","product_id":"515291","quantity":5}'
# Только после явного подтверждения пользователем:
Invoke-RestMethod http://localhost:8000/api/cart/confirm -Method Post -ContentType application/json -Body '{"session_id":"demo-session"}'
Invoke-RestMethod http://localhost:8000/api/cart/demo-session
Invoke-RestMethod http://localhost:8000/api/cart/cancel -Method Post -ContentType application/json -Body '{"session_id":"demo-session"}'
```

Не подключайте `/cart/confirm` к автоматическому эффекту или событию открытия чата: этот POST является отдельным явным действием пользователя.

## Корзина и подтверждение

1. Prepare читает свежую карточку, проверяет количество с учётом уже добавленного и сохраняет ожидающее действие. Корзина остаётся прежней.
2. Подтверждение в чате принимается только по точному списку: «да», «да, добавь», «подтверждаю», «подтверждаю добавление», «да, подтверждаю», `yes`, `confirm` и аналогичным перечисленным в `intent.py`. Вопросы и дополнительные условия не подтверждают действие.
3. Confirm повторно читает карточку и остаток. Неизвестного/недостаточного остатка достаточно для отказа. Успешное действие очищается сразу; повторный confirm не добавляет товар снова.
4. Ожидающее действие действует 5 минут. Смена выбранного товара, новая неоднозначная выдача поиска, отмена или неуспешная повторная подготовка отменяют старое действие. Недостаточный остаток при confirm также очищает действие. Транспортная ошибка оставляет действие для повторной попытки в пределах срока.

Это **локальная демонстрационная корзина**. Никакой резерв товара, заказ или оплата на ekt.kz не создаются. `http://localhost:3000/cart/{session_id}` — работающая страница Next.js из `Frontend/`; учебный режим добавляет `?mode=demo`. Отдельного подтверждённого production cart API нет.

## Поиск, остатки и альтернативы

Поиск просматривает ограниченное число страниц; результаты дедуплицируются по ID, максимум 20 карточек. Страницы кэшируются с TTL, повторный поиск не скачивает каталог заново. `partial:true` означает, что не просмотрен весь каталог или выдача усечена. Отсутствие совпадения не означает отсутствие товара во всём EKT. Серверный поиск пока не подтверждён. Просмотр страниц через `/api/products?page=N` отдельно проверяет первые 5 карточек; если EKT повторяет первую страницу за пределами диапазона, ответ завершает просмотр без дублирования товаров.

Stock-вопросы, карточки и операции корзины всегда идут за свежими данными. В списке EKT остатка нет: поиск отдельно загружает актуальные карточки первых 5 совпадений параллельно. У остальных или при ошибке загрузки остаток остаётся неизвестным, а ответ помечается `partial:true`. Поиск понимает сокращения «АВ», «ВА», `BA` в названиях автоматов и различает 25А/125А.

Альтернативы требуют совпадения раздела каталога и характеристик/номинального тока; конфликтующие характеристики и предупреждения исключаются. Перед выдачей проверяется текущая доступность кандидатов, не более 5 параллельных карточек. Полная взаимозаменяемость не заявляется. Если данных недостаточно или совпадений в просмотренных страницах нет, альтернатив может не быть.

Оплата и доставка возвращают проверенные условия со ссылкой на официальный FAQ EKT (23.09.2026). Единая минимальная партия в проверенных условиях не указана: предлагается уточнение по артикулу у менеджера. Источник и тексты находятся в `conditions_service.py` и доступны через `/api/status`.

## Вложения

Поддерживаемые расширения: `.xlsx`, `.xls`, `.docx`, `.doc`, `.pdf`, `.jpg`, `.jpeg`, `.png`. Принимается один multipart-файл до 10 MiB. Требуется Content-Length; chunked upload не поддерживается. XLSX/DOCX/текстовые PDF читаются в памяти с ограничениями объёма, листов и страниц. Ответ содержит `status:text_extracted`, `analyzed:true`, `extracted_text`. Нераспознанные, старые и сканированные форматы дают `metadata_only` с объяснением. Фото до 4 MiB можно отправить на OpenAI OCR только при `recognize_image=true` и настроенном ключе, вне demo. Файлы не сохраняются на диск; их содержимое не запускает инструменты и не меняет корзину. Подробности и ограничения — в корневом README.

## Тесты и демо

Отчёт закупки обрабатывает до 8 строк с целыми количествами, оставляет неоднозначный выбор пользователю, учитывает повторяющиеся позиции и текущую корзину. В UI каждая строка проходит отдельные prepare и confirm. Сравнение (`product_compare`) возвращает две свежие карточки в существующем поле `products`; неизвестные характеристики не дополняются моделью. Основные ответы RU/KZ определяются языком запроса и сессии.

```powershell
.venv\Scripts\python.exe -m pytest -q
# Проверить HTTP-сервер на localhost:8000:
.venv\Scripts\python.exe scripts/smoke.py
# Полный сценарий на синтетических данных, без сетевого обращения к EKT:
.venv\Scripts\python.exe scripts/demo.py --synthetic
# С настроенным .env и запущенным сервером — настоящее EKT API:
.venv\Scripts\python.exe scripts/inspect_ekt.py
.venv\Scripts\python.exe scripts/demo.py --base-url http://127.0.0.1:8000
```

Сценарий: «Мне нужен автомат на 25А» → выбор ID → наличие → характеристики → сертификат → «Добавь 5 штук» → пустая корзина → «Да, подтверждаю» → 5 единиц и demo URL. Отдельно проверяется нулевой остаток и альтернативы. Тесты также проверяют неизвестные данные, HTTP-ошибки, пагинацию, кэш, изменившийся остаток, изоляцию сессий, отмену и одновременные подтверждения.

## Безопасность и ограничения

- `.env`, `.venv`, временные файлы и логи исключены из Git. В примере окружения пароль пуст. Basic Auth используется только сервером; редиректы отключены, TLS проверяется.
- Пароли не входят в repr настроек, ответы, тестовые fixtures или логи. Не включайте HTTP debug-логирование в окружении с реальными реквизитами.
- Ввод валидируется; ошибки не отражают исходные значения. Платёжные данные не обрабатываются.
- Память процесса очищается при перезапуске. Запускать с **одним worker**; для нескольких процессов нужны общие сессии/хранилище и распределённая блокировка. `--reload` тоже сбрасывает корзины.
- Нет пользовательской авторизации, распределённых сессий, rate limiting, production checkout, резервирования и гарантий доставки запросов. Используйте как локальный хакатонный прототип.
- Поиск по умолчанию ограничен первыми 20 страницами (до 400 товаров на проверенном API) и 8 секундами; это не полный каталог. Детальная нормализация охватывает проверенные свойства; новые свойства/варианты требуют дополнительной инспекции.
- `Frontend/` интегрирован в ветке `integration/test`: новый интерфейс, same-origin proxy, отдельная страница корзины и явно обозначенное автономное демо.

## Дополнительные режимы

`/demo/api/*` использует изолированный синтетический каталог и сессии. `/api/status` и `/demo/api/status` показывают только режим и наличие настроек (без секретов), а также проверенные условия покупки. Опциональный `OPENAI_API_KEY` включает AI-маршрутизацию нераспознанных запросов; модель не имеет намерения подтверждения корзины. Основные сценарии работают без ключа. Настройки и сценарий жюри — в корневом README.
