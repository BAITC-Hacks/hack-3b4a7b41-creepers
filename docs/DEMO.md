# Защита EKT Copilot

## Главная мысль

Закупщик приходит с задачей, артикулом или спецификацией. Сейчас ему приходится искать по каталогу и задавать менеджеру повторяющиеся вопросы. Copilot собирает доступные сведения в одном окне и помогает подготовить список, сохраняя решение о покупке за человеком.

## Критерии из предоставленного регламента

| Критерий | Вес | Что показываем |
| --- | ---: | --- |
| Ценность и решаемая проблема | 25 | Путь от запроса до списка без переключений и ожидания ответов на типовые вопросы |
| Качество результата | 20 | Живой каталог, пустая корзина до подтверждения, актуальный остаток, работающая ссылка, тесты |
| Инновационность | 15 | Ограниченный AI-разбор + сервисы проверяемых фактов + объяснимые аналоги + разбор спецификаций |
| Развитие и масштабирование | 20 | SaaS-план, изолированные интеграции каталога, ясная граница между MVP и production |
| Презентация, демо, ответы | 20 | Воспроизводимый запуск без личного аккаунта; три коротких сценария; честные ограничения |

Это ориентиры из присланного регламента, а не обещание оценки. Решение жюри комплексное. Не называйте прогнозы измеренными результатами.

## Демонстрация на 4 минуты

**0:00–0:30.** Покажите проблему закупщика. Объясните, что продукт сокращает количество ручных переходов; точная экономия времени будет измерена в пилоте.

**0:30–1:30.** Откройте `/?mode=demo`. Покажите маркировку учебных данных. «Проверить наличие» → характеристики → документ → 2 единицы → подготовка → корзина пока пуста → явное подтверждение → корзина и выгрузка. Скажите: EKT-заказ пока не создаётся.

**1:30–2:10.** «Найти замену» для отсутствующего 900003. Объяснение совпадающих параметров, доступный аналог. Полная взаимозаменяемость требует технической проверки.

**2:10–2:40.** Загрузите собственную небольшую XLSX/DOCX спецификацию без персональных данных. Проверьте извлечённый текст, выберите строку, выполните поиск. Покажите условия покупки с источником.

**2:40–3:20.** Переключитесь в реальный режим и запросите `товар 515282`. Доступность зависит от EKT API. Объясните, почему неизвестная валюта или отсутствующий сертификат не подменяются догадкой. При недоступности партнёрского API честно покажите ошибку и продолжите явно обозначенное автономное демо.

**3:20–4:00.** Покажите тесты защиты корзины и следующий шаг: пилот с одним магазином. Фото/свободный казахский запрос показывайте только после добавления ключа и реальной проверки OpenAI.

## SaaS-план — предложение, ещё не реализованная функция

Покупатель SaaS — электротехнический интернет-магазин или дистрибьютор. Конечный пользователь — закупщик. Встраиваемый чат подключается к каталогу, условиям, складским остаткам и авторизованной корзине магазина. Возможная модель — подписка за магазин плюс лимиты использования; цену определять после пилота.

Первый пилот: один магазин, набор типовых запросов, 5–10 закупщиков. Сравнить время до корректного списка с текущим процессом, долю консультаций без менеджера, точность наличия и аналогов, завершённость сценария, количество ошибок и обращений. Показывать медиану и p95 ответа, число проверенных запросов, дату и ограничения выборки. Не обещать «минус 80% времени» без измерений.

Следующие этапы: полный индекс каталога/семантический поиск; фоновые обновления; склады по городам; согласованный checkout; авторизация и хранилище; отдельные данные/ключи/квоты каждого магазина; локализация RU/KZ; мониторинг и управление менеджером. Данные одного арендатора никогда не должны быть доступны другому.

## Короткие ответы жюри

- **Зачем AI, если есть поиск?** Для понимания свободного запроса и чтения маркировки. Факты и действия остаются в проверяемых сервисах.
- **Как боретесь с галлюцинациями?** Модель не сообщает цену и остаток, не подменяет сертификат; backend возвращает нормализованные данные и предупреждения.
- **Может ли промпт добавить товар?** Классификатор модели не имеет операции confirm. Подготовка отделена от явного подтверждения, остаток проверяется повторно, действия сериализуются.
- **Почему аналог релевантен?** Совпадение категории и известных технических параметров, исключение конфликтов, свежая проверка наличия, объяснение в карточке.
- **Можно ли проверить без ваших аккаунтов?** Да: отдельное автономное демо, README и тесты без ключей.
- **Это production SaaS?** Нет, работающий MVP. Checkout, аккаунты, многопользовательское хранилище и эксплуатационные гарантии — следующий этап интеграции.
